# Riemannian Geometry Challenge

A public, open effort to build Riemannian geometry into a living, machine-verified
textbook — a shared foundation anyone can learn from, contribute to, reuse, and
build on.

## The idea

This project explores two questions at once:

- **Can a hypergraph manage natural-language mathematics?** If every definition,
  theorem, and proof becomes a content-addressed node, the prose itself gains
  structure — and that structure is a path toward more efficient formalization.
- **Can formalization, in return, discipline the prose?** With each statement
  paired to a Lean declaration, the formal side checks and constrains the
  natural-language side, which stays as the human-readable UI. Together they
  point toward a decentralized way to manage mathematical knowledge: no single
  authority, just content anyone can verify, reference, and build on.

## How it's stored

The whole project is one **content-addressed hypergraph** — not files and
folders. Every node is a single file named by its hash; documents only reference
them.

\storageTree

Every statement, declaration, and relation is one immutable entry
`(hash, ref, record)`. Identity *is* content: the same content always hashes to
the same id, so cards dedupe, merge, and re-reference without ambiguity. An
**atom** (one self-reference) is a leaf — a statement or proof.

\atomExample

An **edge** (two references) is a *typed* relation between atoms — `references`,
`uses`, `corollary-of`, `formalizes`, and more — a typed network, not a bare
dependency tree.

\edgeExample

**Two layers, one graph.** *tex* atoms hold the natural-language statements;
*lean* atoms hold the formal declarations that prove them, joined by cross-source
`formalizes` edges. A node's hash is pinned to *what it is*, not its current text,
so a proof going from `sorry` to `proven` updates in place without churning the
graph.

Numbers like "Theorem 3.2.1" are **derived from where a card first appears, never
stored** — reorder a section and everything renumbers itself.
