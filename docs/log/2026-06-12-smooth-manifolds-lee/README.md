## 问题定义

这批材料是**以教材为顺序组织的形式化**：一个编号一个文件（`Chap05/Sec05_29/Theorem_5_8.lean`）、import 图与章节编号深度耦合、设施代码（图卡操作、截断函数、实例打包）散落在各章定理的脚下随用随造。

而我们要的是**可复用性、可维护性、可延伸性极高的软件**：声明按数学对象组织成模块、设施沉淀为共用层、上层（黎曼几何、几何测度论）只 import 设施而不知道教材的存在。

所以核心问题是：**教材序形式化 → 软件库的转化要怎么做，并且做成可重复执行的流程**——因为这不是最后一次有人带着一整本书的形式化来敲门。

## 核心目标

1. 高价值内容（子流形、切片图卡、浸没、覆盖映射、带边流形）以我们的约定进入主干，填补"Mathlib 流形机器 → 黎曼度量层"之间缺失的中间层。
2. 转化过程中持续把工程开销剥离进共用设施层（本次已识别五层：打包类、图卡演算、截断/单位分解、切丛局部化、子流形抽象），不允许第二套平行设施出现。
3. 流程本身沉淀为可复用资产：下一个 `import/*` 分支来时，审计、判重、移植、质检走同一条流水线。

自动化循环：

```
领单 → ① 通用层判定（AI 输出 复用/扩展/新建 决策表，必须附 grep 证据）
     → ② 移植（AI：换命名空间、按落点重组、每条声明补 Math./Eng. 双 docstring）
     → ③ 机器门（CI：全量构建、零 sorry、linter 基线、命名与出处行检查）
     → ④ 自动开 PR（附决策表与台账销单 diff）
     → ⑤ 人审（只审两项，见下节）
```

两条常驻约束（写进模板，不靠口头提醒）：

1. **通用层优先**：未回答"主分支是否已有同型设施"之前不许写代码。本次审计已验证其价值——两边各写了同一组设施的一半，不强制判重就会出现第二套。
2. **语义符合**：每条移植声明带 Math./Eng. 双 docstring（范例见 `Riemannian/TangentBundle/TangentSmooth.lean`）。存在性由 linter 把守，忠实性由人审把守。

自动化的终点是 PR，不是 develop。人始终是合并的守门员。

## 人的部分：核心节点与语义评审分配

依据最小可信基（minimal trusted base）论证：Lean 内核已检查全部证明，**证明不需要人审**；但定义错了，内核会毫无怨言地让我们证明几千行关于错误对象的真命题。人审的全部对象收缩为**定义与定理陈述**，且其中定义错误的代价（废掉整个下游依赖锥）远高于定理陈述错误（只废自己）。

评审分配算法：

1. **核心节点清单**：依赖图入度高的 `def`/`class`/`structure` 自动入选（本次实测：`IsEmbeddedSubmanifold` 被引 18 次、`TopologicalManifold` 17 次——这些是承重墙），人工增补语义微妙的低入度定义；`theorem` 一般不入选。
2. **CODEOWNERS 强制**：核心节点文件映射到数学专家，动这些文件的 PR 没有 owner 批准不能合并。
3. **专家只审两件事**：Math. docstring 与陈述是否同一个数学对象；核心定义的实例化测试是否存在且非平凡（堵"假设不可满足、空洞为真"的漏洞，example 放 `Tests/`）。
4. **非核心节点**：AI 审 + 人工抽查。

一句话：内核消灭了证明审查，剩余审查负担集中在可信基上，可信基里承重的是依赖图枢纽——把枢纽用 CODEOWNERS 钉给专家，用最少的专家时间买到全局正确性。
